# API Monitor

Приложение для мониторинга доступности внешних HTTP API и веб-сервисов. API Monitor периодически отправляет GET-запросы к зарегистрированным адресам, измеряет время ответа, сохраняет результаты проверок и показывает состояние сервисов в веб-интерфейсе.

## Возможности

- Регистрация API по названию и URL.
- Просмотр списка активных API и получение API по UUID.
- Логическая деактивация API без удаления его истории.
- Ручной запуск проверки через REST API и веб-интерфейс.
- Автоматическая проверка всех активных API по расписанию.
- Измерение времени HTTP-ответа.
- Сохранение истории проверок с датой, HTTP-кодом и результатом.
- Постраничное получение истории: по умолчанию 20 записей, максимум 100; новые проверки отображаются первыми.
- Валидация входных данных и обработка основных ошибок API.
- Автоматическое удаление результатов проверок старше 90 дней.
- Веб-панель с общей статистикой, списком API и историей проверок.
- Отдельная in-memory база H2 для тестов.

## Как работает мониторинг

1. Пользователь регистрирует API, указывая название и URL.
2. API сохраняется в файловой базе H2.
3. Планировщик Spring получает список активных API и последовательно запускает их проверку.
4. Для каждого адреса отправляется HTTP GET-запрос с таймаутом 10 секунд.
5. Приложение измеряет время выполнения запроса и сохраняет результат проверки.
6. Веб-интерфейс периодически запрашивает актуальные данные и обновляет отображение.

Автоматический мониторинг использует `@Scheduled(fixedDelay = 60_000)`: следующий цикл начинается через 60 секунд после завершения предыдущего цикла. Поэтому при большом количестве API или медленных ответах фактический интервал между проверками может быть больше минуты. Проверки выполняются последовательно.

### Статусы проверки

| Статус | Значение |
|---|---|
| `SUCCESS` | Сервер вернул HTTP-статус из диапазона 200–299. |
| `HTTP_ERROR` | Сервер ответил, но HTTP-статус не входит в диапазон 200–299. |
| `TIMEOUT` | Запрос не завершился за установленный таймаут. |
| `NETWORK_ERROR` | Во время запроса произошла сетевая ошибка. |

`responseTimeMs` — время выполнения HTTP-запроса в миллисекундах, а не ICMP ping. В текущей реализации проверяется доступность HTTP-эндпоинта и код ответа; содержимое и бизнес-логика ответа не анализируются.

### Хранение истории

- Рабочая база H2 хранится на диске в `./data/apimonitor`.
- Результаты проверок старше 90 дней удаляются автоматически каждый день в 03:00 по часовому поясу `Europe/Berlin`.
- История деактивированных API сохраняется, пока не наступит срок очистки.
- Тесты используют отдельную базу H2 в памяти и не должны изменять рабочую базу.

## Запуск

### Требования

- JDK 25.
- Git — для клонирования репозитория.

### Запуск приложения

Клонируйте репозиторий и перейдите в его каталог:

```bash
git clone https://github.com/24kaaa/api-monitor.git
cd api-monitor
```

На Windows запустите приложение через Maven Wrapper:

```bat
mvnw.cmd spring-boot:run
```

На Linux/macOS:

```bash
./mvnw spring-boot:run
```

После запуска откройте веб-интерфейс:

```text
http://localhost:8080/
```

Приложение автоматически создаёт файловую базу в каталоге `data`, если он ещё не создан.

### Запуск тестов

Windows:

```bat
mvnw.cmd clean test
```

Linux/macOS:

```bash
./mvnw clean test
```

Тестовая конфигурация находится в `src/test/resources/application.properties` и использует отдельную in-memory базу H2.

## Веб-интерфейс

Веб-интерфейс находится в `src/main/resources/static/index.html` и раздаётся самим Spring Boot. Отдельная сборка frontend и установка npm-пакетов не требуются.

В интерфейсе доступны:

- просмотр активных API и сводной статистики;
- регистрация нового API;
- ручной запуск проверки;
- просмотр истории проверок с пагинацией;
- деактивация API.

Интерфейс обновляет отображаемые данные периодическими запросами к REST API. Сам мониторинг продолжает работать на сервере независимо от того, открыт ли браузер.

## REST API

Базовый адрес при локальном запуске: `http://localhost:8080`.

| Метод | Эндпоинт | Описание |
|---|---|---|
| `GET` | `/api/monitored-apis` | Получить список активных API. |
| `POST` | `/api/monitored-apis` | Зарегистрировать API. |
| `GET` | `/api/monitored-apis/{id}` | Получить API по UUID. |
| `DELETE` | `/api/monitored-apis/{id}` | Деактивировать API (логическое удаление). |
| `POST` | `/api/monitored-apis/{apiId}/checks` | Запустить проверку API вручную. |
| `GET` | `/api/monitored-apis/{apiId}/checks` | Получить историю проверок с пагинацией. |

### Регистрация API

Запрос:

```http
POST /api/monitored-apis
Content-Type: application/json
```

Тело:

```json
{
  "name": "Public API",
  "url": "https://api.example.com/health"
}
```

`name` не может быть пустым. `url` обязателен и должен начинаться с `http://` или `https://`.

### Получение истории проверок

По умолчанию возвращается первая страница из 20 записей. Максимальный размер страницы — 100 записей.

```http
GET /api/monitored-apis/{apiId}/checks?page=0&size=20
```

- `page` — номер страницы, начиная с `0`.
- `size` — число записей на странице, от `1` до `100`.
- Сначала возвращаются самые новые результаты (`checkedAt` по убыванию).

Ответ имеет формат Spring Data `Page`: записи находятся в `content`, метаданные пагинации — в `number`, `size`, `totalElements`, `totalPages`, `first` и `last`.

### Основные HTTP-ошибки

| HTTP-статус | Ситуация |
|---|---|
| `400 Bad Request` | Некорректные поля запроса или параметры пагинации. |
| `404 Not Found` | API с указанным UUID не найден. |
| `409 Conflict` | Попытка повторно зарегистрировать активный URL или проверить неактивный API. |

## Конфигурация

Основные настройки находятся в `src/main/resources/application.properties`:

```properties
spring.application.name=api-monitor

spring.datasource.url=jdbc:h2:file:./data/apimonitor
spring.datasource.username=sa
spring.datasource.password=

spring.jpa.hibernate.ddl-auto=update

spring.h2.console.enabled=true
```

Консоль H2 доступна по адресу `http://localhost:8080/h2-console` при запущенном приложении. Для локального подключения используется JDBC URL `jdbc:h2:file:./data/apimonitor`, пользователь `sa` и пустой пароль — согласно приведённой конфигурации.

Не используйте настройки локальной H2-консоли и пустой пароль как готовую конфигурацию публичного production-развёртывания.

## Примечания

- Приложение ориентировано на мониторинг HTTP GET-эндпоинтов.
- Результат `SUCCESS` означает успешный HTTP-статус, но не гарантирует корректность бизнес-данных или полную работоспособность всех функций внешнего сервиса.
- Публичные API могут ограничивать частоту запросов или менять правила доступа. Перед добавлением внешнего сервиса следует проверить его условия использования.
- Для публичного развёртывания потребуются дополнительные меры: защита интерфейса и API, управление конфигурацией, резервное копирование базы, а также контроль частоты запросов.
